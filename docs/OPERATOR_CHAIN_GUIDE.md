# MiSub 操作符链 (Operator Chain) 完全指南

MiSub 的核心灵魂在于其强大的节点处理引擎。从 v2.5.0 版本开始，我们引入了**操作符链 (Operator Chain)** 架构，将节点转换逻辑从硬编码升级为高度可定制的流式管道。

---

## 1. 核心概念：什么是操作符链？

操作符链类似于工业生产流水线。每一个“操作符 (Operator)”都是一个独立的加工工序：
1. **输入**：原始节点列表（来自机场订阅或手动输入）。
2. **加工**：按照您设定的顺序，依次执行过滤、重命名、排序等操作。
3. **输出**：最终生成的、符合您需求的干净节点列表。

> [!TIP]
> **继承机制**：在“订阅组”中，如果您不配置任何操作符，系统将自动使用“全局设置”中的默认链。如果您在订阅组中单独配置，则会完全覆盖全局设置。

---

## 2. 内置操作符详解

### 🛒 过滤节点 (Filter)
通过多种维度精准控制节点的去留。
- **协议限制**：仅保留 vless, hysteria2 等特定协议。
- **地区限制**：通过内置算法识别香港、日本等常用地区。
- **包含/排除正则**：使用正则表达式匹配节点名称。
- **脚本过滤**：支持自定义逻辑。
- **精简模式**：自动剔除已过期的、流量超限的或名称中含有“流量额度”等无效节点。

### 🏷️ 节点重命名 (Rename)
重塑节点名称，使其在客户端中整齐划一。
- **正则替换**：将 `香港 01` 替换为 `HK-01`。
- **模板重写**：支持占位符，如 `{emoji}{region}-{protocol}-{index}`。
  - `{emoji}`: 自动添加国旗。
  - `{regionZh}`: 中文地区名。
  - `{index}`: 自动递增序列号。
  - **索引分组**：`{index}` 的计数方式可选 全局 / 按地区 / 按协议 / 按地区+协议 / **按名称**。选“按名称”时，**同名节点**各自从 1 递增，配合模板 `{name}-{index}` 可实现“同名加序号”。

### 🔢 节点排序 (Sort)
定义节点的优先级。可以添加多个排序条件（Weight），按照先后顺序作为主次关键字。
- **常用排序**：按地区升序 -> 按协议升序 -> 按名称升序。

### 🧹 智能去重 (Dedup)
基于服务器地址和端口的指纹识别，自动合并多份订阅中重复的节点，保持列表清爽。

### 🔟 数量限制 (Limit)
限制输出节点数量，适合“每个地区只保留 N 个”的场景。
- **保留数量**：每组最多保留的节点数（正整数，非法值会被忽略、不清空）。
- **分组方式**：全局 / 按地区 / 按协议 / 按地区+协议 / 按名称。按**当前顺序**每组保留前 N 个。
- **顺序建议**：放在 **排序 (Sort) 之后**，先排好序再截断，结果才确定（例如先按延迟/地区排序，再每地区留前 3）。

---

## 3. 🛡️ 脚本操作符 (Script) —— 终极定制

脚本操作符用一套**声明式、受限**的处理规则 (DSL JSON) 来过滤、丢弃、改名和改写节点，由服务端解释执行，**不运行任意 JavaScript**（旧的 `code` / `url` 自定义脚本字段已停用）。

完整语法、动作、条件与模板函数见 **[处理规则 DSL 指南](./OPERATOR_DSL_GUIDE.md)**。

## 4. 常见问题 (FAQ)

**Q: 我应该把操作符放在全局还是订阅组？**
A: 如果大部分机场的处理方案一致，建议放在“全部设置”。对于特殊的“直连组”或“流媒体专线”，可以在订阅组中单独定制。

**Q: 操作符的执行顺序有影响吗？**
A: **非常有影响！** 通常建议的顺序是：
`去重 (Dedup) -> 过滤 (Filter) -> 重命名 (Rename) -> 排序 (Sort) -> 数量限制 (Limit)`。
先过滤掉不需要的节点，再对剩下的节点进行重命名和排序，最后按需截断数量，效率最高。
